# Borrowed and Lent: v1.11.2

Android code 20. This feature is included in v1.11.3; the checks below were performed locally before publication.

Add Loan now offers Borrowed (money received) and Lent (money given). Per the user's clarification, lending has exactly two funding sources: Cash Balance and Bank Balance. A new lending deducts from the selected wallet. Borrowing adds to the selected wallet. Outstanding debt and receivables are displayed separately as I Owe and Owed to Me.

Partial/full collections reduce the receivable and add actual money to the chosen receiving wallet. Existing receivables can be recorded without repeating an old cash movement. Deleting a loan removes its linked payments and recalculates the affected wallets.

## Validation

The repeatable real-API integration journey is `node --env-file=.env.local scripts/check-lending-wallets.mjs` (browser) or the same command with `--native` (Android debug WebView forwarded to 9325). It creates a uniquely named temporary account and removes its user/session/cloud records afterward. Native requests are forwarded to the local production API on port 3005; responses are real, not simulated.

The journey starts with bank Tk10,000 and cash Tk5,000. It checks:

1. Borrow Tk5,000 into bank: bank15,000/cash5,000; debt5,000.
2. Lend Tk2,000 from bank: bank13,000/cash5,000; receivable2,000.
3. Lend Tk1,000 from cash: bank13,000/cash4,000; receivable3,000.
4. Collect Tk500 into cash: bank13,000/cash4,500; receivable2,500.
5. Clear the remaining bank lending into bank, and cash lending into cash: bank14,500/cash5,500; receivable0.
6. Repay borrowing partly from bank, then fully from cash: bank12,500/cash2,500; debt0.
7. Record existing receivable without changing balances; collect Tk100 and check the balance increases only then.
8. Delete the test loans and linked payments: bank10,000/cash5,000 restored.
9. Add Tk300 lending offline, reload, then reconnect: cash4,700 persists and the lending reaches the real API.

Browser and actual Android SQLite execution both passed all steps with zero runtime errors, including real API sync after offline reload. Wallet regression and responsive 320/390/900 checks passed. Unit/regression suite, TypeScript, ESLint, production website build and signed Android build passed. The signed release is installed in the emulator and shown in the existing EXPTRACK - Android window. Test users/cloud records are removed by exact scoped cleanup.
