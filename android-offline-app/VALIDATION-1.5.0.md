# EXPTRACK 1.5.0 - Loans

Android versionCode 10. Loans are associated with cash movements using versioned metadata in the existing ledger. Each borrowing/repayment is saved atomically with its cloud outbox change using the existing IndexedDB/SQLite paths; no database migration or new API contract is required. Outstanding debt is calculated separately from available cash. Existing debt entries are excluded from cash totals; new money received increases cash, and actual repayments reduce cash. Existing Loan received entries are recognized without creating another receipt.

Loans includes active/cleared/all filters, total outstanding/borrowed/repaid, lender, dates, progress, partial/full repayments and retained repayment history. Browser locks serialize repayments for the same loan across local tabs. Independently recorded payments from different offline devices are retained; any overpayment appears as a credit warning rather than silently dropping cash movements.

Validation: scripts/check-loans.mjs passed borrowing-to-cash calculations, existing debt without cash impact, decimal partial repayment, full clearing, history, reload, legacy loan recognition, invalid zero/over-limit/sub-cent repayments, offline saving/reconnect and a second-client sync simulation. The test uses isolated sample accounts and a simulated sync endpoint, not real Google login or production account writes. Inspected light/dark and 320/390/1280 pixel layouts; no horizontal overflow or runtime errors. Corrected selected-button hover contrast in dark mode. TypeScript, targeted ESLint and the mobile export passed. Signed release/debug builds and signature/alignment checks are performed by scripts/build-android.ps1, with the release SHA-256 alongside the APK.

Update the website and Android installations together for correct interpretation of existing-debt records. Install over the old APK, without uninstalling, to preserve local records. Real-device Google sign-in and reminder delivery were not retested for this release; those integrations are unchanged.

Native validation: scripts/check-native-loans.mjs passed on the API 35 emulator using the built debug WebView and SQLite plugin: new borrowing, existing debt, partial and full repayments, reload persistence, correct cash totals, and the bundled /loans route. Auth and sync were intercepted with a disposable local account; no production account records were written.
