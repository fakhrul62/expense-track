# EXPTRACK 1.7.0 - Multiple expenses in one popup

Android versionCode 13. New expense entry starts with the familiar single editor. The fixed header places + Add Another immediately left of Close, so the action remains reachable with the number pad open. On phones the popup fills the app viewport without an empty top margin. Add Another keeps the current draft and starts another with the same date/category. Up to 20 entries can be recorded together. Review expenses reveals compact editable/removable rows; it stays collapsed during entry. Each draft has its own amount/category/date/note. The fixed footer shows count, total and Save all. Income and existing-entry editing retain single-entry behavior.

Browser saves expenses and their sync-outbox changes in one IndexedDB transaction. Android uses the new account-guarded ExpenseStore.putBatch bridge method with a single SQLite transaction for all expense and outbox changes. There is no schema migration or server API change. Draft UUIDs remain stable across retries, and a synchronous submission guard prevents repeated Save clicks from inserting duplicates. A failed batch retains the form instead of saving only some records.

Validation: scripts/check-batch-expenses.mjs verifies mixed categories/dates/notes, edit/remove, totals, double-submit, reload, cancel, ordinary entry editing, income, and rollback when a category disappears. Browser screenshots at 320/390 pixels in both themes were visually inspected. TypeScript and targeted ESLint passed. The --native option passed the same core journeys through the debug WebView and directly verified that a failed SQLite batch leaves both records and outbox unchanged. Auth and sync in these checks are simulated with an isolated account. The APK build script verifies release signatures/alignment and writes a SHA-256 checksum alongside the artifact.
