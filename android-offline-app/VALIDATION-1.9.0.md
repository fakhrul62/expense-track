# EXPTRACK 1.9.0 - Borrowed and lent loans

Android versionCode 16. Add Loan contains I Owe (borrowed) and Owed to Me (lent) choices. Main filters are Active (outstanding borrowing), Cleared (settled both directions), Owed to Me (outstanding lending), and All. The selected direction has its own outstanding/principal/settled totals; mixed views show borrowed and lent outstanding totals separately. Every loan card identifies the direction. Borrowed loans retain repayment actions; lent loans record money received, partially or in full. Existing loans without direction metadata are borrowed by default.

The existing versioned loan envelope gains an optional direction field, keeping the account-specific SQLite/IndexedDB/outbox storage and cloud protocol. New lending uses a Money lent expense category; payments back use the existing Owed money repaid income source. Borrowing increases cash and repayment decreases it; lending decreases cash and collection increases it. Existing debt only changes the loan total, and subsequent cash payments are recorded normally. No destructive migration is performed.

scripts/check-loan-directions.mjs passed browser checks for both directions, partial and full settlements, filters and non-netted mixed totals, cash balances, existing lending without duplicate cash, reload, legacy borrowing, offline lending and simulated second-client restoration. Light/dark screenshots at 320/390 pixels were visually inspected. TypeScript and targeted ESLint passed; Android release/debug builds and signature/alignment verification use the normal build script. --native runs the same financial paths through the debug SQLite plugin with simulated auth/sync. No production account data is touched by those tests. Install over the existing app to retain records. Update all devices for the new loan direction labels and filters. Native Google sign-in and timed reminder delivery are unchanged and not retested for this release.

Release build completed with v2/v3 signature and alignment checks. The release descriptor matches the delivered APK. Direct .NET SHA256 hashing replaced Get-FileHash in the packaging script after a local command-discovery failure. New loan creation selects the matching direction filter so the saved record is immediately visible.
